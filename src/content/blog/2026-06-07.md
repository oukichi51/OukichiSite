# プロジェクトマネジメントの実行のプロセス群とは

**実行のプロセス群**とは、プロジェクトマネジメントにおいて、  
計画した内容を実際に進め、成果物を作っていくためのプロセスのまとまりです。

PMBOKでは、プロジェクトマネジメントのプロセス群は主に次の5つに分けられます。

1. 立上げプロセス群
2. 計画プロセス群
3. 実行プロセス群
4. 監視・コントロール・プロセス群
5. 終結プロセス群

この中で、**実行のプロセス群**は、プロジェクト計画書に沿って作業を進め、成果物を作成する段階にあたります。

---

## 実行のプロセス群の目的

実行のプロセス群の目的は、計画で決めた内容をもとに、  
人・予算・情報・品質・調達などを動かしながら、プロジェクトの作業を進めることです。

簡単に言うと、  
**「計画を実際の行動に移す段階」** です。

---

## 主な活動

実行のプロセス群では、次のような活動を行います。

| 活動 | 内容 |
|---|---|
| プロジェクト作業の指揮・マネジメント | 計画に沿って作業を進め、成果物を作成する |
| 品質のマネジメント | 品質基準を満たすように作業方法を管理する |
| 資源の獲得 | 必要な人員・設備・ツールなどを確保する |
| チームの育成 | メンバーの能力や協力体制を高める |
| チームの管理 | メンバーの作業状況や課題を管理する |
| コミュニケーションのマネジメント | 関係者に必要な情報を共有する |
| リスク対応策の実行 | 計画していたリスク対策を実施する |
| 調達の実行 | 外部業者との契約や発注を行う |
| ステークホルダー・エンゲージメントのマネジメント | 関係者の期待や関与を調整する |

---

## 計画プロセス群との違い

計画プロセス群と実行プロセス群の違いは、次のように整理できます。

| プロセス群 | 役割 |
|---|---|
| 計画プロセス群 | 何を、いつ、誰が、どのように行うかを決める |
| 実行プロセス群 | 計画に基づいて、実際に作業を進める |

つまり、  
**計画プロセス群は「準備」**、  
**実行プロセス群は「実施」**  
と考えるとわかりやすいです。

---

## 監視・コントロールとの関係

実行のプロセス群では、計画どおりに作業を進めます。

しかし、実際のプロジェクトでは、予定どおりに進まないこともあります。

そのため、実行と同時に、  
**監視・コントロール・プロセス群**によって、進捗・品質・コスト・リスクなどを確認します。

問題が見つかった場合は、必要に応じて計画を修正したり、対応策を実施したりします。

---

## 具体例

たとえば、Webサイト制作プロジェクトの場合、実行のプロセス群では次のような作業を行います。

- デザイナーが画面デザインを作成する
- エンジニアがフロントエンドを実装する
- ライターが記事コンテンツを作成する
- プロジェクトマネージャーが進捗会議を行う
- クライアントに進捗状況を共有する
- 外部パートナーに作業を依頼する
- 発生したリスクへの対応策を実施する

---

## まとめ

実行のプロセス群とは、  
**プロジェクト計画に基づいて、実際に作業を進め、成果物を作るためのプロセス群**です。

計画を立てるだけでは、プロジェクトは完了しません。

実行のプロセス群では、チームを動かし、関係者と連携しながら、  
プロジェクトの目的を達成するための作業を進めていきます。

# プロジェクトマネジメントの計画プロセス群とは

**計画プロセス群**とは、プロジェクトの目的を達成するために、  
**何を、いつ、誰が、どのように進めるかを具体的に決めるプロセスのまとまり**です。

PMBOKでは、プロジェクトマネジメントのプロセス群は主に次の5つに分けられます。

1. 立上げプロセス群
2. 計画プロセス群
3. 実行プロセス群
4. 監視・コントロール・プロセス群
5. 終結プロセス群

この中で、**計画プロセス群**は、プロジェクトを実行する前に、作業の進め方や管理方法を明確にする段階にあたります。

---

## 計画プロセス群の目的

計画プロセス群の目的は、プロジェクトの目標を達成するために必要な作業や手順を整理し、  
実行のための準備を整えることです。

簡単に言うと、  
**「プロジェクトを成功させるための道筋を決める段階」** です。

---

## 主な活動

計画プロセス群では、次のような活動を行います。

| 活動 | 内容 |
|---|---|
| プロジェクトマネジメント計画書の作成 | プロジェクト全体の進め方や管理方法をまとめる |
| スコープの定義 | プロジェクトで何を作るのか、どこまでを対象とするのかを明確にする |
| WBSの作成 | 作業を細かく分解し、管理しやすくする |
| スケジュールの作成 | 作業の順序や期間、完了予定日を決める |
| コストの見積り・予算設定 | 必要な費用を見積もり、予算を決める |
| 品質計画 | 成果物に求められる品質基準や確認方法を決める |
| 資源計画 | 必要な人員、設備、ツールなどを計画する |
| コミュニケーション計画 | 誰に、いつ、どのような情報を共有するかを決める |
| リスク計画 | 想定されるリスクを洗い出し、対応策を考える |
| 調達計画 | 外部から購入・委託するものや契約方法を決める |
| ステークホルダー・エンゲージメント計画 | 関係者との関わり方や調整方法を決める |

---

## 実行プロセス群との違い

計画プロセス群と実行プロセス群の違いは、次のように整理できます。

| プロセス群 | 役割 |
|---|---|
| 計画プロセス群 | 何を、いつ、誰が、どのように行うかを決める |
| 実行プロセス群 | 計画に基づいて、実際に作業を進める |

つまり、  
**計画プロセス群は「準備・設計」**、  
**実行プロセス群は「実施・作業」**  
と考えるとわかりやすいです。

---

## 監視・コントロールとの関係

計画プロセス群で作成した計画は、プロジェクトを進めるうえでの基準になります。

実行中には、実際の進捗・コスト・品質などを確認し、  
計画との差がないかを監視・コントロールします。

もし予定より遅れていたり、コストが超過していたりする場合は、  
計画を見直したり、対応策を実施したりします。

そのため、計画プロセス群で作成する計画は、  
**実行や監視・コントロールの基準になる重要なもの**です。

---

## 具体例

たとえば、Webサイト制作プロジェクトの場合、計画プロセス群では次のような作業を行います。

- Webサイトの目的や対象ユーザーを整理する
- 作成するページや機能の範囲を決める
- デザイン、開発、テストなどの作業を洗い出す
- 作業スケジュールを作成する
- 必要なメンバーや外部パートナーを決める
- 制作費用を見積もる
- 品質確認の方法を決める
- クライアントとの報告頻度や会議体を決める
- 納期遅延や仕様変更などのリスク対応を考える

---

## まとめ

計画プロセス群とは、  
**プロジェクトをどのように進め、管理していくかを具体的に決めるためのプロセス群**です。

計画が不十分なまま実行に進むと、作業の抜け漏れ、スケジュール遅延、予算超過、品質低下などが起こりやすくなります。

計画プロセス群では、スコープ・スケジュール・コスト・品質・資源・リスクなどを整理し、  
プロジェクトを円滑に進めるための土台を作ります。
